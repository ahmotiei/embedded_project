# متن پیشنهادی گزارش بخش سوم

## 3.1 معماری پردازش تصویر

در این بخش مسیر دوربین به‌صورت `Host Agent → Vision Relay → C Web Core` تغییر داده شد. Host Agent فریم خام JPEG را با یک header چهار بایتی شامل طول فریم روی TCP پورت 9200 ارسال می‌کند. ماژول vision پس از تشخیص و رسم اطلاعات الزامی، فریم پردازش‌شده را با همان protocol به وب‌سرور C روی loopback پورت 9100 می‌فرستد. این طراحی موجب می‌شود endpoint استریم بخش دوم بدون تغییر API، خروجی نهایی دارای کادر، شمارنده، شماره دانشجویی، زمان و FPS را ارائه کند.

## 3.2 مدل تشخیص

مدل HOG/SVM آماده OpenCV استفاده شد. پس از `detectMultiScale`، کادرهای تکراری با Non-Maximum Suppression حذف شدند. FPS از تعداد فریم‌های پردازش‌شده در بازه زمانی واقعی محاسبه و روی تصویر درج شد.

## 3.3 ایمیل و debounce

ارسال ایمیل در برنامه C با libcurl و MIME انجام شد. متن ایمیل شامل تعداد افراد، timestamp، دمای CPU و FPS است و snapshot لحظه تشخیص به‌صورت JPEG پیوست می‌شود. مقدار زمان آخرین ایمیل در `/var/lib/smart-guard/last_email_epoch` ذخیره می‌شود. اگر فاصله رخداد جدید با ایمیل قبلی کمتر از 30 ثانیه باشد، رخداد suppress شده و در journal ثبت می‌شود. ذخیره state روی دیسک مانع دورزدن debounce با restart سرویس می‌شود.

## 3.4 MQTT

Broker Mosquitto روی کامپیوتر شخصی و client در C روی VM اجرا شد. anonymous access غیرفعال و احراز هویت username/password و ACL فعال است. پیام‌ها با QoS 1 روی topicهای `telemetry/401102553/home` و `persons/401102553/home` منتشر می‌شوند. LWT retained روی `status/401102553/home` تنظیم شده است.

## 3.5 ترتیب وابستگی سرویس‌ها

```text
network-online.target
        │
        ▼
smart-guard-web.service
        │ Requires + After
        ▼
smart-guard-vision.service
        │ Requires + After
        ▼
smart-guard-mqtt.service
```

علت ترتیب: وب‌سرور C باید پیش از vision آماده دریافت فریم پردازش‌شده باشد و notifier نیز باید پس از آماده‌شدن C telemetry و فایل رخداد vision اجرا شود.

## آزمایش 3-4 — LWT و بازیابی Broker

- تصویر پیام `offline-unexpected` پس از kill ناگهانی client.
- تصویر reconnect و پیام `online` پس از بازگشت Broker.
- توضیح: Broker در زمان خاموشی خودش نمی‌تواند LWT منتشر کند؛ LWT با قطع غیرمنتظره client در حالی که Broker فعال است اثبات شد و خاموش/روشن‌کردن Broker برای recovery آزمایش شد.
